一张照片从存储卡到网页，中间有很多可以偷懒的环节。但偷懒的代价通常由读者承担：加载慢、颜色脏、手机上糊成一片。

这篇记录我目前的流程。它不追求专业，只追求**稳定、可重复、不占太多时间**。

## 一、选片：先删，再挑

导入之后先做减法：

- 连拍只留一张；
- 失焦、手抖、曝光完全救不回来的，直接删；
- 同一场景保留不超过三张。

选片的标准不是"哪张最好"，而是"哪张值得被再看一次"。一个下午能选出十张，已经很多了。

## 二、调色：克制

我主要用 Lightroom，原则是**先修好，再风格化**：

1. 校正白平衡和曝光；
2. 拉回高光，提一点阴影；
3. 用曲线做一次轻微对比；
4. 最后才考虑色温和分离色调。

EVA 配色看多了，很容易把所有照片都调成紫绿。但照片首先要像它当时的样子，风格是后面的事。

## 三、导出：为网页准备

网页图片和印刷图片是两种东西。我的导出设置：

| 参数 | 相册大图 | 文章插图 |
| --- | --- | --- |
| 长边 | 2000px | 1400px |
| 格式 | JPEG | JPEG / WebP |
| 质量 | 82 | 80 |
| 色彩空间 | sRGB | sRGB |
| 元数据 | 保留版权，删除位置 | 同左 |

关键是 **sRGB**。很多浏览器对其它色彩空间的处理并不一致，导出前转成 sRGB 能避免"我这里很好看，别人那里发灰"。

## 四、命名：给未来的自己看

不要用 `IMG_2043.jpg`。我的命名格式是：

```text
2026-09-wuhan-night-01.jpg
```

日期、地点、主题、序号。半年后搜索 `wuhan` 还能找到，换电脑也不会丢上下文。

## 五、上传：两种图片，两条路径

这个博客把图片分成两类：

**文章插图**放在 `public/images/posts/`，在 Markdown 里直接引用：

```md
![夜晚的江面](/images/posts/2026-09-river-01.jpg)
```

**相册图片**放在 `src/assets/photos/`，然后在 `src/data/photos.ts` 里追加一条记录。构建时 Astro 会自动生成多尺寸版本，手机上不会下载一张 4000px 的原图。

```ts
{
  src: p7,
  title: '江边的风',
  alt: '夜晚江面上的灯光倒影',
  album: '光影',
  date: '2026.09',
  caption: '风把水面吹皱，灯光碎成一片。',
}
```

## 六、让照片在网页上好看

几个小细节比滤镜更重要：

- **控制尺寸**：正文里的图片不要超过容器宽度，大图点开再看。
- **写好 alt**：既是无障碍，也是图片加载失败时的兜底。
- **加一句 caption**：照片需要一点上下文，哪怕只是一句话。
- **不要滥用全屏大图**：除非它真的值得。

## 最后

流程的价值在于，当你不想拍照的时候，它仍然能保证输出不会太差。剩下的时间，留给真正重要的事：出门，观察，按下快门。
